# FamilyFlow API · Фаза 0

Аккаунты, облачное хранение бюджета, приглашения в семью.

## Эндпоинты
| Метод | Путь | Что делает |
|---|---|---|
| POST | /auth/register | {email, password, familyName} → token; создаёт семью и пустой state |
| POST | /auth/login | {email, password} → token |
| GET | /family/me | моя семья: имя, роль, invite_code, число участников |
| POST | /family/invite | (owner) генерирует 6-значный код приглашения |
| POST | /family/join | {code} → вступить в семью, вернёт её state |
| GET | /state | снапшот бюджета семьи + updatedAt |
| PUT | /state | {data, baseUpdatedAt} → сохранить; 409 при конфликте |
| POST | /auth/delete-account | {password} → безвозвратно удаляет аккаунт (152-ФЗ); если владелец не единственный участник — семья передаётся следующему |
| GET | /health | проверка живости и БД |

Авторизация: заголовок `Authorization: Bearer <token>`.

## Деплой на Timeweb Cloud

1. **База**: панель → Базы данных → создать PostgreSQL (минимальный тариф).
   Скопируйте строку подключения (DATABASE_URL).
2. **Репозиторий**: создайте на GitHub `familyflow-api`, запушьте эту папку.
3. **Приложение**: панель → App Platform → создать приложение → Node.js →
   репозиторий familyflow-api, ветка main.
   - Build: `npm install`
   - Run: `npm start`
4. **Переменные окружения** приложения:
   - `DATABASE_URL` — из шага 1
   - `JWT_SECRET` — длинная случайная строка (например `openssl rand -hex 32`)
   - `CORS_ORIGIN` — https-адрес фронтенда
   - `DATA_ENC_KEY` — обязательно перед боевым запуском, иначе бюджет семьи (финансовые
     ПДн) хранится в БД в открытом виде; см. `.env.example` как сгенерировать
   - остальные переменные из `.env.example` (ЮKassa, почта, push, Sentry/GlitchTip) —
     по мере подключения соответствующих функций
5. Деплой. Схема БД применится автоматически при первом старте.
6. Проверка: откройте `https://<api-домен>/health` → `{"ok":true}`.

## Локальный запуск
```bash
cp .env.example .env   # заполнить
npm install
node --env-file=.env server.js
```

## Тесты

Интеграционные тесты (`test/*.test.js`) поднимаются на реальном Postgres —
чистой in-memory заглушки для БД сознательно нет, чтобы проверять настоящие
транзакции (лимит участников семьи, удаление аккаунта, дедуп чекаута). ЮKassa
подменяется мок-модулем (`jest.mock('../lib/yookassa')`) — сеть и боевые ключи
не нужны.

```bash
# локально нужен Postgres, доступный без пароля/с паролем postgres:
export TEST_DATABASE_URL=postgresql://postgres@localhost:5432/familyflow_test
npm test
```

В CI (`.github/workflows/ci.yml`) база поднимается как сервис-контейнер
`postgres:16` — ничего дополнительно настраивать не нужно, прогон идёт на
каждый push и pull request в `main`.

## Резервное копирование

Приложение само по себе бэкапов не делает — это ответственность управляемой БД.

1. В панели Timeweb Cloud → Базы данных → выбранная БД включите автоматическое
   резервное копирование (обычно ежедневное) и задайте срок хранения копий
   (рекомендуется не меньше 7 дней, для боевого запуска лучше 14–30).
2. Периодически (например раз в квартал) проверяйте, что восстановление из
   бэкапа реально работает — бэкап, который ни разу не разворачивали, нельзя
   считать надёжным.
3. `DATA_ENC_KEY` бэкапом БД не покрывается (это переменная окружения
   приложения, не данные в БД) — храните её отдельно, например в менеджере
   паролей. Потеря ключа делает все зашифрованные бюджеты нечитаемыми навсегда,
   даже если сама БД восстановлена из бэкапа.
